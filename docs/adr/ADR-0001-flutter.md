# ADR-0001: Выбор Flutter как основного UI-фреймворка

**Статус:** Предварительно принято  
**Дата:** 2026-08-09  
**Версия:** 0.1

## Контекст

LifeOS планируется как долгосрочный кроссплатформенный проект.

Первоначальная целевая платформа — ПК.

В дальнейшем необходимо предусмотреть возможность запуска LifeOS на:

- Windows;
- macOS;
- Linux;
- Android;
- iOS;
- Web.

Основные требования к технологическому стеку:

- единая кодовая база;
- высокая скорость разработки;
- хорошая производительность;
- современный пользовательский интерфейс;
- возможность масштабирования;
- поддержка desktop и mobile;
- возможность изолировать платформозависимый код;
- хорошая интеграция с локальным хранилищем;
- возможность интеграции AI;
- долгосрочная поддержка проекта.

## Рассмотренные варианты

### Flutter + Dart

Преимущества:

- единый UI-фреймворк для desktop и mobile;
- единая кодовая база;
- высокая производительность;
- собственный рендеринг интерфейса;
- развитая экосистема;
- хорошая поддержка Windows, macOS, Linux, Android и iOS;
- удобная работа с адаптивными интерфейсами;
- удобен для создания сложных приложений с единым визуальным стилем.

Недостатки:

- Dart менее распространён, чем JavaScript/TypeScript;
- некоторые desktop-сценарии могут потребовать нативного кода;
- web-версия не является первичной целью Flutter;
- необходимо внимательно выбирать библиотеки для desktop и local-first архитектуры.

### TypeScript + React Native / Electron

Преимущества:

- огромная экосистема JavaScript;
- большое количество разработчиков;
- большое количество библиотек;
- удобная разработка web-приложений.

Недостатки:

- React Native и Electron решают разные платформенные задачи;
- desktop и mobile архитектура может потребовать больше платформенной специфики;
- Electron может потреблять значительное количество памяти;
- сложнее обеспечить единый архитектурный подход для desktop и mobile.

### C# + .NET / .NET MAUI

Преимущества:

- зрелая платформа;
- сильная типизация;
- развитая экосистема .NET;
- хорошая производительность;
- удобна для enterprise-разработки.

Недостатки:

- меньше единообразия UI между платформами;
- экосистема мобильного и desktop UI менее привлекательна для концепции LifeOS;
- потенциально больше платформозависимого кода.

## Решение

В качестве основного UI-фреймворка LifeOS предварительно выбирается:

**Flutter**

Основной язык:

**Dart**

## Причины выбора

Главная причина выбора Flutter — необходимость построить единый продукт, который начинается с desktop и потенциально развивается в mobile без полной переработки пользовательского интерфейса.

Flutter позволяет использовать единую технологическую основу для:

```text
                 LifeOS
                    |
             Flutter / Dart
                    |
        ┌───────────┼───────────┐
        ↓           ↓           ↓
     Desktop      Mobile       Web
        |           |           |
    Windows       Android      Browser
    macOS         iOS
    Linux
